# ADR-002：以可维护的本地事实库作为长期记忆的默认实现

- 状态：记录当前实现；后续改进项不构成已批准的开发计划
- 日期：2026-09-22
- 范围：`dsh-ltm` 0.1 的架构定位、取舍与重新评估条件
- 相关：[ADR-001 检索方案](adr-semantic-search.md)、[数据模型](data-model.md)、[需求](requirements.md)

## 背景与目标

“长期记忆”不是单一技术问题：用户偏好和项目事实、历史经历、操作经验、当前任务进度，需要不同的保存与召回机制。文件、关系数据库、向量检索和知识图谱也不是互斥的架构。

本项目选择一个明确目标：**让个人 Agent 跨会话保存、找回和维护少量高价值事实**，例如用户偏好、项目约定、决策及其原因、难以从代码直接恢复的踩坑经验。

不以聊天全文归档、海量文档问答、自动学习全部操作经验或多租户知识平台为目标。临时任务进度应使用任务清单或 checkpoint；仓库已有的知识优先读取其事实来源，避免在记忆中维护第二份过时副本。

## 决策

沿用以下默认实现，不引入强制 embedding、外部服务或图数据库：

1. **模型显式写入事实。** 通过记忆工具决定保存什么，不在后台自动扫描全部对话并生成摘要。
2. **SQLite 保存原文及生命周期字段。** 正文与派生 FTS5 索引在同一事务中维护；索引可以从原文重建。
3. **词项召回加字符相似度重排。** 中文切为单字与相邻双字，英文按 ASCII 词段切分；FTS5 匹配后按 BM25 排序并截取候选，再混合字符 2～3 gram 余弦分数。
4. **有限自动召回加主动查询。** 提示词优先放置顶记忆，再放近期记忆，受字符预算限制；其余由模型按需搜索。
5. **允许修订、合并、确认和删除。** 同 scope 的近重复检测减少重复写入；`stale` 提醒复核，但不自动删除事实。
6. **核心独立于集成层。** 插件与 CLI 复用存储和工具语义，避免两套行为。

这一选择是对当前约束的工程取舍，不是对所有 Agent 记忆场景的最优性声明。

## 为什么暂不增加更复杂的方案

| 方案 | 可能带来的收益 | 当前不作为默认实现的原因 |
|---|---|---|
| 全量历史或持续摘要 | 保留对话细节或延续任务状态 | 本项目聚焦独立事实；全文增加筛选成本，摘要又会丢失细节并可能失真 |
| 本地 embedding | 改善同义表达及低词项重叠查询的召回 | 需要模型、推理依赖和索引维护；尚需本项目评估证明增益 |
| 托管 embedding | 降低本机推理负担 | 引入网络、费用、服务可用性和数据发送边界，不宜成为必需项 |
| 时间知识图谱 | 显式表示实体关系、有效期和事实演变 | 增加抽取、消歧与更新复杂度；不能自行保证抽取的事实正确 |
| 纯文件笔记 | 易读、易编辑、便于人工维护 | 同样是合理方案；本项目选择数据库以支持按 ID 修改、事务、标签筛选和索引一致性 |

Embedding 可以本地运行；“本地优先”不等于排斥 embedding。当前只预留 `EmbeddingAdapter` 接口，没有接入实现，也不承诺某个版本一定引入。

## 接受的限制与准确语义

### 检索不是事实判断，也不是完整语义理解

当前字符余弦向量来自字符片段计数，不是模型生成的语义 embedding。没有足够词项重叠时，候选可能根本未进入 FTS 结果；候选截取后的重排无法找回它们。相似度高也不代表两条陈述相同、没有矛盾或仍然有效。

当前权重 `BM25_WEIGHT = 0.6` 是代码常量，不是公开配置项。没有基准证据时，不承诺固定容量上限、延迟上限或相对其他系统的优势。

以上澄清优先于 ADR-001 中“模糊语义信号”“权重可配”、特定规模与 `<10ms` 等较强表述。字符重排可能改善已有候选的顺序，但不能据此声称具备同义词召回能力；未来 embedding 也不应被限定为只替换重排公式，可能需要改变候选召回。

### 去重有规模成本，但不解决矛盾

非强制写入在 `BEGIN IMMEDIATE` 后读取同 scope 的全部记录，计算 Jaccard / 字符余弦近重复。成本随记录数量和文本长度增长，也会占用写事务时间。它适用于个人事实集合，不应无评估地扩展为海量文档库。

近重复检测只提示相似记录，不判断新事实应覆盖旧事实，或两者是否适用于不同项目、时间和条件。

### scope 不是安全隔离边界

`defaultScope` 显式配置，不从 Git 或目录自动推断。写入采用该 scope；工具搜索在默认 scope 非空时限定范围，空时搜索全库。自动提示词召回目前从全库选取；按 ID 更新和删除也不构成 scope 访问控制。

因此不能把当前 scope 当成项目之间或用户之间的权限隔离。

### 过期标记不是有效期模型

`stale` 根据 `lastConfirmedAt` 动态计算，默认 90 天未确认就提示复核。它不表示事实已经错误，不记录事实的完整有效时间区间，也不会自动删除。`update` 修改内容不等于 `confirm`；确认也只是调用方的操作，不是系统独立验证了真实性。

### 本地存储不代表信息永不出机

存储和检索无需外部模型服务，但被选入提示词或工具结果的记忆会进入所选 LLM 的上下文。不要存储秘密。渲染时打断模板定界符的转义也不是通用提示词注入防护；记忆内容不应因此获得更高指令权限。

## 已知缺口

- 缺少结构化来源字段，难以直接追溯到原始消息或证据。
- 缺少显式的事实有效期、替代关系与冲突处理模型。
- scope 尚未贯穿所有读取和修改路径，不能提供安全隔离。
- 缺少针对本项目真实使用场景的端到端效果评估。
- 保存与搜索的触发依赖模型；改进数据库或排序不能独立解决“没写入”“没调用搜索”。

这些缺口需要按实际失败模式排序，而不是因某种架构流行就一次性全部引入。

## 重新评估的触发条件

| 观察到的失败 | 优先评估方向 | 判断依据 |
|---|---|---|
| 同义改写经常漏召回 | 查询扩展、可选 embedding / 混合召回 | 低词项重叠样本的正确召回是否改善，成本是否可接受 |
| 新旧事实或适用范围混淆 | 来源、有效期、替代关系和复核规则 | 过时引用与冲突误答是否减少 |
| 多项目或多用户记忆串用 | 一致的命名空间及访问控制 | 所有读写路径能否通过隔离测试 |
| 写入延迟或锁等待增长 | 去重候选缩小、预计算等优化 | 实际数据分布下的延迟、锁等待及漏判率 |
| 记录存在但模型不去查 | 工具说明、检索触发与上下文组织 | 相同数据和预算下的端到端任务成功率 |
| 经常需要回答历史事件与操作过程 | 保留可追溯事件记录或接入原始历史检索 | 事实条目之外的信息是否确有必要，而非重复归档 |

## 验证方式

新增架构之前，先建立不含秘密的小型固定回归集，至少覆盖：

- 精确词项、中英文混合、单字及同义改写查询。
- 事实更新、否定句、不同时间或项目下同时成立的陈述。
- 重复写入、修订、合并、明确删除及重新确认。
- 没有证据时不编造答案，旧事实不能被误当成最新事实。
- 置顶和近期记忆超过提示词预算时的行为。
- 从不同 scope 发起查询和其他操作时的实际可见范围；以当前语义作为基线，不能把它误记为隔离已通过。

同时测量检索结果与端到端行为：相关记录命中率、过时或错误引用、无证据误答、任务成功率、工具调用与 token 成本、读写延迟。比较方案时固定模型、输入数据、提示词和调用预算；效果与性能分别报告。

厂商 benchmark 可以提供实验线索，但不同模型、数据导入、工具轮数和评分方式下的数字，不直接作为本项目选型依据。

## 参考与判断边界

以下资料提供背景，不构成其作者对本项目方案的背书：

- [LangMem：长期记忆类型与召回条件](https://www.langchain.com/blog/langmem-sdk-launch)，2025-02-18。支持先区分事实、经历与操作经验，再选择实现。
- [Anthropic：有效的上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)，2025-09-29。讨论有限上下文、按需检索、压缩与结构化笔记的组合。
- [LongMemEval](https://arxiv.org/abs/2410.10813)，ICLR 2025。将评估扩展到多会话推理、时间推理、知识更新和拒答，而不只看关键词召回。
- [Letta：文件系统记忆实验](https://www.letta.com/blog/benchmarking-ai-agent-memory/)，2025-08-12。提示需评估 Agent 的工具使用能力；其文件检索包含 embedding，不能解读为纯文件或 grep 普遍优于向量检索。

**结论：保留当前简单、可维护的默认方案，以可复现的真实失败决定升级方向。优化目标是减少重复交代与错误记忆，而不是增加存储或检索组件的数量。**
